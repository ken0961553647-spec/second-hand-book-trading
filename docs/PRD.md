# 校園二手書交易平台 PRD

## 一、專案概述

### 1.1 背景與動機
在大學校園中，教科書昂貴與學期末書籍閒置是學生長期面臨的真實現狀。每學期數千元的書本費用對學生是不小的負擔，而課程結束後，許多保存良好的書籍往往被堆在宿舍角落。雖然現有的電商平台可供交易，但存在面交排程困難、運費不划算以及無法精確搜尋校園特定課程用書等問題。因此，我們希望打造一個專屬於校園、以「學程/課程」為核心分類的二手書平台，活化校園資源並減輕學生經濟壓力。

### 1.2 目標用戶
**大學生**。許多大學生花費大量金錢購買上課用書，但課程結束後這些書便閒置，造成資源浪費。透過本平台，擁有閒置書籍的學生可以賣給需要這些書的其他學生，達到資源互惠與減少浪費的目的。

### 1.3 核心價值主張（系統預期解決的問題）
1. **建立精準搜尋機制**：整合學校課程大綱，讓使用者能直接透過「系所」或「課程名稱」快速找到對應教材。
2. **優化校園面交流程**：內建預約系統，方便買賣雙方在校園地標（如圖書館、校門口）約定時間，並提供安全交易指南。
3. **降低交易門檻**：免除第三方寄送成本與手續費，並透過學生身分認證（學校信箱）提升交易信任度。
4. **推動永續循環**：透過統計功能顯示本學期減少的碳足跡與節省的金額，提升學生的參與意願。

## 二、需求分析（Requirements Analysis）

### 2.1 功能性需求（Functional Requirements）
系統「必須能做到」的事情，包含以下核心功能：

| 功能編號 | 功能名稱 | 功能描述 |
| --- | --- | --- |
| F-01 | 線上交易 | 於線上進行交易行為 |
| F-02 | 商品上架 | 能夠上架書籍 |
| F-03 | 搜尋功能 | 能使用關鍵字快速搜尋到想要的書 |
| F-04 | 使用者登入 | 使用學校帳號登入 |
| F-05 | 個人化願望清單 | 使用者可追蹤特定書籍，當有賣家上架該書時，系統自動發送通知提醒 |
| F-06 | 即時通訊系統 | 提供買賣雙方即時溝通管道，可針對書況詢問、議價或約定面交時間地點 |
| F-07 | 訂單管理與追蹤 | 提供個人管理後台，讓使用者查看當前進行中、已完成或已取消的買賣紀錄 |

### 2.2 非功能性需求（Non-functional Requirements）
系統的品質要求，例如效能、安全性、易用性等：

| 類別 | 需求描述 |
| --- | --- |
| 效能 | 能在兩天內將交易完成 |
| 安全性 | 對互相交易過的使用者帳號進行評價，能一眼看出對方評價高低以此判斷是不是可以進行交易的對象 |
| 易用性 | 能簡單就上手 |

### 2.3 範圍限制（Out of Scope）
明確說明這次專題「不會」做的功能，避免範圍膨脹。

**本次不包含**：
- 折價券系統
- 二手書預約系統
- 二手書退還和退費系統

## 四、MVP 範圍 (Minimum Viable Product)

### Must Have (必須擁有 - 核心功能)
- 學生學校信箱註冊與登入（基礎身分驗證）。
- 書籍上架功能（包含照片、書名、價格、對應課程）。
- 課程/系所分類瀏覽與關鍵字搜尋功能。
- 基礎面交預約功能（留言或約定狀態切換）。

### Should Have (應該擁有 - 提升體驗)
- 買賣雙方即時通知（預約確認、留言通知）。
- 碳足跡與節省金額統計顯示。
- 簡單的賣家/買家評價機制。

### Nice to Have (可以擁有 - 未來擴充)
- 線上金流代收付（若未來考慮非現金面交）。
- 整合校務系統 API（自動匯入當學期課表）。
- 願望清單功能（當所需書籍上架時自動通知）。

## 六、風險評估（Risk Assessment）
預測專案開發與平台上線後可能遇到的困難，以及因應策略。

| 風險 | 發生可能性 | 影響程度 | 因應策略 |
| --- | --- | --- | --- |
| 詐騙與惡意棄單 | 中 | 極高 | 建立評價系統與檢舉機制，並推薦於校園內公共地標作為安全交易地點。 |
| 個資外洩風險 | 中 | 很高 | 使用 HTTPS 加密協定，對使用者密碼進行雜湊處理，並僅要求註冊與交易之必要資料。 |
